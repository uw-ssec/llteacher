# Requirements
* [Data access is tenant-scoped: repositories take a branded scope, and routes check ownership](tenant-scoped-data-access.md) - Routes never query Drizzle directly; every repository function takes OrgScope/CourseScope minted from AuthContext; conversation-mutating routes must verify row ownership first; course id is never taken from a request body for tools.
* [Identity PII is encrypted at rest with AES-256-GCM, and lookups go through HMAC blind indexes](identity-pii-encrypted-at-rest.md) - No plaintext email, netid or display name is ever written to users; encryption and blind-index keys are separate, env-loaded, never committed; Drizzle relational joins must not read encrypted columns.
* [Production secrets come only from GitHub environment secrets and Secrets Manager, never from code, logs, or arguments](production-secrets-handling.md) - Production values live as GitHub production-environment secrets, validated and redacted before any AWS mutation, delivered via two generated Secrets Manager secrets read only by the ECS execution role; local creds stay local.
* [Database migrations must finish before new application code serves traffic](migrate-before-deploy.md) - Every deploy path runs Drizzle migrations to completion (and validates concurrent indexes) before the new task/bundle is activated; migration failure blocks activation. Rollback of code after a forward migration must stay safe.
* [The TS port must reach Django feature parity first, and deviations must be written down](django-parity-baseline.md) - Milestones M1-M5 target parity with the legacy Django app (accounts, homeworks, conversations, LLM config, R execution); behavior changes from Django must be recorded as resolved design decisions, not drift.
* [Only one process may ever write a course's knowledge bundle or run material extraction](single-writer-knowledge-and-extraction.md) - Exactly one app process writes each course's OKF working copy and S3 manifest and runs extraction; no concurrent tasks, rolling overlap, local processes or recovery commands against the same course.
* [Students get read-only knowledge tools, scoped to their own course, and material is treated as untrusted](student-knowledge-access-read-only.md) - Students reach the knowledge base only via searchKnowledge/showKnowledge, course forced from their conversation; all write ops are instructor-of-course routes; uploaded content is data, never instructions.
* [All regional AWS resources live in us-west-2, and deploys refuse a stack whose region is stale](aws-region-us-west-2.md) - Every regional resource (including ACM for the ALB) is in us-west-2; IAM/Route 53 are global. Releases verify aws:region=us-west-2 before mutation and an existing us-east-1 stack must be migrated deliberately, never reconfigured.
* [FERPA and HIPAA data-protection items are still open: audit, deletion, retention, and LLM payloads](ferpa-data-protection-open-items.md) - Open compliance gaps: audit_events append-only only at app layer (#50), student_profiles plaintext (#137), no FERPA hard-delete path, org delete cascades grades/logs/audit, no LLM-payload PII guard (#52), HIPAA tenant unresolved.
* [Stakeholder requirement: usable for fall-quarter 2026 pilots](stakeholder-fall-quarter-pilot.md) - PIs need the platform working for courses starting about end of September 2026; issues labelled must-complete: fall-quarter (19 open, M7 RAG and M12 infra/cutover) define the minimum.
* [Stakeholder requirement: tutor and homework modes, code as bonus, leveled prompts](stakeholder-homework-modes-and-assistance-levels.md) - PIs need two core modes (open tutor sessions with course context; professor-defined homework worked through in sections), with code assignments as a bonus mode, plus professor-set prompts and assistance levels.
* [Stakeholder requirement (unresolved): aggregate vs individual student data for instructors](stakeholder-instructor-visibility-of-student-data.md) - The nursing-informatics PI asked for aggregate-only performance views, conflicting with Django-parity transcript viewing and grading; decision #78 is open and gates analytics and per-student drill-ins.
* [Stakeholder requirement: tutoring grounded in each course's own materials, per assignment](stakeholder-course-grounded-tutoring.md) - PIs want the tutor grounded in their uploaded course materials (lectures, slides, notes, exams) rather than generic answers, with different materials per assignment, plus agentic fetch of allowlisted external sources.
* [Stakeholder requirement: help instructors see where students have knowledge gaps](stakeholder-knowledge-gap-insight.md) - PIs want quiz and interaction data turned into per-topic knowledge-gap signals so instructors (or the tutor) can target follow-up work and adaptive quizzes; tracked in M8 and constrained by #78.
